# map-stop 产品与技术说明（v0.1）

> 仓库：https://github.com/CoderL98/map-stop  
> 状态：v1 转向高德算路 + 可插拔 RoutingProvider；开源自托管为二期  
> 语言：产品界面与文档默认中文

---

## 1. 产品一句话

做一个网页版路线规划工具：系统维护「躲避点库」，用户规划时**硬避开**所有生效禁区（绝对不进入，靠绕路）；用户也可添加自定义点，或上传候选点经管理员审核后升为系统点。

---

## 2. 背景与约束

| 约束 | 约定 |
|------|------|
| 版权与费用 | v1 使用高德须遵守其条款与配额/商用授权；二期可切开源自托管以降依赖 |
| 地图实现 | v1：**高德** Web 服务 + JS API（降低初期成本）；同一接口预留二期自托管开源路由；不默认百度/腾讯 |
| 躲避语义 | 绝对不经过躲避点位，通过绕路实现；不可达则明确失败，不降级穿行 |
| 点位来源 | 管理员配置/导入系统点；用户自定义；用户上传 → 审核 → 系统点 |

---

## 3. 角色与权限

### 3.1 用户（user）

- 注册 / 登录
- 设置起点、终点，选择出行方式，发起路线规划
- 管理个人**自定义躲避点**（增删改、调半径、规划时勾选是否生效）
- **上传**候选躲避点（地图标注或 CSV）
- 查看本人上传记录与审核状态（待审 / 通过 / 驳回及原因）

### 3.2 管理员（admin）

- 具备用户全部能力
- 系统躲避点：CRUD、启停、批量 CSV 导入
- 审核队列：通过（写入系统库并启用）/ 驳回（需填写原因）
- 种子管理员：可通过环境变量在首次启动时创建

### 3.3 账号

- **正式登录**（用户名或邮箱 + 密码）
- 角色：`user` / `admin`
- 自定义点、上传单、审核记录等**按账号持久化**

---

## 4. 躲避点模型

每个躲避点至少包含：

| 字段 | 说明 |
|------|------|
| 名称 | 必填 |
| 纬度、经度 | 必填 |
| 避让半径（米） | 必填，可配置；系统默认 **80** |
| 来源 | `system` / `custom` / `upload` |
| 状态 | 系统点：`enabled` / `disabled`；上传：`pending` / `approved` / `rejected` |
| 备注 | 可选 |
| 归属用户 | 自定义点、上传单必填；系统点可空或记录导入者 |
| 时间戳 | 创建/更新时间 |

### 4.1 规划时生效集合

```
生效禁区 = 全部 enabled 的系统点
         ∪ 当前用户勾选的自定义点
```

- 未审核通过的上传点**不进入**系统库，不对他人生效
- 审核通过后，对新发起的规划**立即生效**

### 4.2 空间形态

- 首版：**点 + 可配置半径 → 圆形硬禁区**
- 不做：线段禁区、任意多边形编辑器（可列为二期）

### 4.3 算路规则（硬避开）

1. 将每个生效圆近似为避让多边形（或引擎支持的 avoid 几何）
2. 调用开源路由引擎求路径
3. **服务端二次校验**：结果折线不得与任一禁区圆相交；若相交则视为失败
4. 无可行路：返回明确错误（如「无法完全避开指定点位，请缩小半径或减少躲避点」）
5. **禁止**静默穿行或「尽量避开」降级（首版不做软约束模式）

### 4.4 数量上限（默认）

- 单次规划生效躲避点建议上限：**50**
- 超出时提示用户缩小集合或分批，不静默截断导致误导

## 5. 功能范围（MVP）

### 5.1 规划页（用户）

1. 地图展示（高德 JS 优先；无 Key 时 Leaflet/OSM + CRS 标注）
2. 设置起点 / 终点：点击地图、搜索地名、拖动标记
3. 出行方式：驾车（默认）/ 步行 / 骑行
4. 自定义躲避点列表：勾选、调半径、删除；地图上画圆
5. 「规划路线」：展示折线、距离、预估时间
6. 修改点位或半径后可重算
7. 加载中 / 失败提示

### 5.2 上传与审核

- 用户：地图添加或 CSV 上传候选点
- CSV 模板（UTF-8）：`名称,纬度,经度,半径米,备注`
- 管理员：待审列表；通过 / 驳回

### 5.3 系统点管理

- 列表、搜索、启停、编辑
- 批量 CSV 导入（同模板）
- 导入校验：必填列、经纬度范围、半径 > 0

### 5.4 明确不做（首版）

- 实时路况、公交、多途经点最优排序
- 组织/多租户、复杂权限
- 多边形/线禁区编辑器
- 原生 App、支付、社交
- 百度 / 腾讯商用 SDK（高德已作为 v1 默认算路/底图选项）

## 6. 技术架构

```text
浏览器
  SvelteKit (pnpm) + 高德 JS API 2.0（有 Key）/ Leaflet 回退
        │
        ▼
Rust API
  认证 / 点位 / 审核 / 导入 / 规划编排与硬约束校验
        │
        ├─ 数据库（账号、系统点、自定义点、上传与审核）坐标 CRS 见 meta
        └─ RoutingProvider（可插拔）
              ├─ gaode      （v1 默认，高德 Web 服务路径规划）
              ├─ embedded   （杭州网格 A*，无 Key 演示）
              └─ opensource （二期 stub：GraphHopper / Valhalla）
```

### 6.1 前端

- **SvelteKit** + **pnpm**
- 规划 / 管理 / 上传页：有 `AMAP_JS_KEY` 时用 **高德 JS API 2.0**；否则 Leaflet + OSM（标注 CRS）
- 地名搜索：gaode 模式走高德输入提示/地理编码；embedded 走 Nominatim 代理
- 只请求自家 Rust API；通过 `GET /api/meta/routing` 获知 provider / CRS / JS Key

### 6.2 后端

- **尽量 Rust**：业务 API、认证、点位与审核、规划编排、**所有 provider 的几何硬校验**均在 Rust
- **RoutingProvider**：`ROUTING_PROVIDER` + `AMAP_WEB_KEY` 选择后端；开源引擎二期接入同一接口
- 数据库：SQLite（可迁 PostgreSQL）；**高德路径下点位按 GCJ-02 存储**
- 认证：JWT；密码 argon2；管理员种子账号环境变量初始化

### 6.3 工程形态

- 目录：`apps/web` + `services/api`（`routing/{embedded,gaode,opensource}.rs`）
- README：本地启动、高德 Key 申请、环境变量、CSV、版权与切换路径
- `.env.example`：数据库、JWT、管理员、`ROUTING_PROVIDER`、`AMAP_*` 占位（勿提交真实 Key）

### 6.4 版权与费用策略

| 组件 | 策略 |
|------|------|
| 底图 / 算路（v1） | 高德：遵守高德开放平台条款与配额；商用需授权 |
| 地理编码（v1） | 高德输入提示 / geo；embedded 回退 Nominatim |
| 开源路径（二期） | GraphHopper/Valhalla + OSM，同一 RoutingProvider |
| CRS | 高德路径 **GCJ-02**；勿与未转换 WGS84 混用 |

## 7. 主要用户流程

### 7.1 规划

登录 → 设起点/终点 →（可选）勾选自定义点 → 规划 → 查看绕开系统点+自定义点的路线 → 调整后重算

### 7.2 上传入库

用户上传候选 → 状态待审 → 管理员通过 → 写入系统库并启用 → 之后所有用户规划均需避开

### 7.3 管理员导入

管理员上传 CSV → 校验 → 写入系统点（默认启用或按导入选项）→ 全站生效

---

## 8. 验收标准

1. 管理员导入的系统点，任意登录用户规划时都被硬避开（路线不进入圆）
2. 用户自定义点仅本人规划可选；不影响他人
3. 上传点未通过前不进系统库；通过后对新规划立即生效
4. 不可达时有清晰中文错误，不穿行
5. 改半径/点位后可重算
6. 界面中文；本地可通过文档所述方式启动（pnpm + Rust + compose 等）
7. 地图有 OSM 署名；仓库含本说明与 CSV 模板示例
